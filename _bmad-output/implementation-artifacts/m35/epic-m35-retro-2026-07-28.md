## Key Technical Correction

The late blocking issue was not renderer geometry. Backend LSP tests saw M35 graphic occurrences, but the Theia smoke path saw zero because the M35 professional projection only initialized after source editor `didOpen`.

Fix: `AthenaProjectionSessionProtocol.kt` now loads and tracks the M35 source-backed projection graph-first. A regression test in `AthenaM35DedicatedCabinetProjectionSmokeTest.kt` proves the Cabinet projection works before editor `didOpen`.

This matters because Graph view must not depend on an editor side effect to show the authoritative project projection.

## Lessons

- Cabinet must remain a compiled projection of engineering truth, not a second semantic world.
- SVG can be useful for complex vendor geometry, but it must only point to geometry. Athena source owns anchors, roles, compatibility, ports, and meaning.
- Graph view initialization must be source-backed and projection-backed, not dependent on editor lifecycle.
- E2E proof must combine screenshots with structured proof. Screenshot-only approval is too easy to fake or misunderstand.
- Because Athena is unreleased, stale compatibility paths should be removed when they violate the architecture.

## M36 Handoff

Protect these boundaries:

- Athena source remains SSOT.
- XML is out of the active product path unless explicitly justified as a private converter input.
- Physical installation remains a projection layer, not the Engineering Component System.
- General constraint solving and auto-layout are still deferred.
- Future vendor/resource package work should keep package identity separate from filesystem layout.
- Bidirectional editing must flow through governed intent, source mutation, compile, and rerender.

Recommended next focus: Engineering Component System foundation, with strict separation between product identity, physical constraints, representation elements, symbols, and drawing primitives.
