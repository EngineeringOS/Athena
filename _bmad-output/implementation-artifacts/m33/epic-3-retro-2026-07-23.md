# Epic 3 Retrospective - Graphic Primitive Compilation And SVG Adapter

## Epic Review

Epic 3 completed all three stories. The native ten-symbol catalog now compiles from Drawing Symbol
Anatomy into validated Graphic Primitive IR, renders through one generic SVG fragment adapter, and
is wrapped by a root composer whose viewBox derives from IR bounds and governed margin policy.

Final verification passed sequentially: svg-renderer and LSP module suites, all 203 frontend tests,
all 147 Gradle tasks, and the repository encoding audit.

## What Worked

- TDD exposed missing production orchestration, full-circle arc collapse, unsafe XML, sweep
  workload, and derived-viewBox overflow before story closeout.
- `M33IecSymbolCatalog` remained the only native inventory authority from package compilation
  through LSP rendering.
- Graphic Primitive IR stayed generic; IEC package knowledge and SVG syntax never moved into it.
- Fragment painting and root canvas composition remained separate responsibilities.
- Explicit safety facts reject toy regressions without parsing SVG, DOM classes, coordinates, or
  label text for engineering meaning.
- Every story completed AC-to-evidence, adversarial review, and polish/purge accounting.

## Challenges

- The old `SvgRenderer`, `PresentationSvgPath`, and frontend `svg_path` path still have live
  M30-M32 compiler/runtime/Workbench callers. Removing them in Epic 3 would have broken active
  behavior, so migration remains explicit debt rather than hidden cleanup.
- File-like native resource names initially looked resolved but had no governed runtime meaning.
  Exact `athena-native:<resource-id>` handles were required before rendering could be trusted.
- Finite source numbers do not guarantee finite derived geometry. Extreme bounds plus margin
  overflowed before serialization and required a second validation gate.
- Renderer proof needed owning authority as a required transport field, not optional metadata.

## Lessons

1. A professional drawing pipeline needs separate definition, compilation, primitive painting,
   and root composition authorities.
2. Bounds proof must validate the derived result, not only each finite input.
3. Safety evidence belongs upstream as explicit facts; SVG/DOM inspection is only a test guard.
4. Active compatibility code must be migrated with product evidence before deletion.
5. A production consumer is required in the same story that claims a new pipeline is usable;
   module-only model tests are insufficient.

## Previous Follow-Through
