# Epic 2 Retrospective - Native IEC-Style Symbol Package

## Epic Review

Epic 2 completed all three stories. It established an Athena-owned IEC-style package scaffold,
seven core power/control symbols, three terminal/reference symbols, exact anchor/slot contracts,
and a ten-symbol catalog backed by Drawing Symbol Anatomy and Graphic Primitive IR.

Verification completed sequentially on Windows. Final Story 2.3 regression passed all 147 Gradle
tasks, and repository encoding audits passed after documentation updates.

## What Worked

- TDD exposed missing contracts before implementation, especially multi-descriptor package binding.
- Existing M32 package/profile/binding contracts and M33 anatomy/primitive validators were reused.
- `bindingPolicyTags` removed alphabetical descriptor selection and now fail closed for missing,
  mismatched, duplicate, or ambiguous mapping.
- Shared symbol construction was extracted before terminal/reference additions, leaving cohesive
  files below the repository's Kotlin organization threshold.
- Route evidence proves descriptor anchors and explicitly rejects center fallback.
- Every story recorded AC evidence, adversarial review, and polish/purge results.

## Challenges

- The original Story 2.x files were skeletal and lacked BMAD Tasks/Subtasks and developer context.
  Each story required a create-story quality pass before development.
- M32 claimed descriptor selection but only supported one descriptor per package in practice. The
  first multi-symbol package exposed this gap.
- Initial style reuse made connection dots transparent and text dependent on line-work styling;
  focused visual-contract tests corrected both before renderer integration.
- Story 2.2 tests initially assumed the package would permanently contain exactly seven entries;
  Story 2.3 corrected this to a stable core-library contract plus an extensible package catalog.

## Lessons

1. A package containing multiple representation descriptors requires an explicit, validated
   selection policy. Deterministic alphabetical fallback is not semantic resolution.
2. Symbol libraries, package catalogs, and shared symbol-building support are separate ownership
   roles and should remain separate in names and files.
3. Visual semantics such as filled dots, text paint, label roles, and reference slots need
   structured tests before an SVG adapter exists.
4. Route correctness must be proven from descriptor anchors; a center fallback is never acceptable
   evidence for the professional demo.
5. File-like Graphic Resource paths are not proof that a resource exists or resolves. Epic 3 must
   define the native anatomy-to-resource/primitive path explicitly.

## Previous Follow-Through

No Epic 1 retrospective artifact existed. Its sprint action to keep Drawing Symbol Anatomy generic
was satisfied: IEC naming remains inside the package-runtime implementation while anatomy and
Graphic Primitive IR contracts remain generic in `kernel/representation-model`.

## Next Epic Preparation

Epic 3 compiles symbol anatomy to Graphic Primitive IR and introduces the SVG adapter. It must:

- consume `M33IecSymbolCatalog` as the single native symbol inventory authority;
- resolve or replace the current logical `resources/athena-iec-*.vector` handles rather than assume
  files exist;
- preserve entry-level binding policy selection and no-fallback diagnostics;
- avoid a second primitive model, raw SVG authority, DOM inference, or hard-coded viewBox;
- keep renderer output downstream of validated anatomy, package, and binding facts.
