# M34 PRD Memlog

- decision: M34 corrects M33 XML package fragmentation by introducing Athena-owned Symbol/Element definitions.
- decision: Symbol is atomic; Element is reusable composite; Cabinet is composed from element instances.
- decision: SVG is a visual carrier; Athena metadata is the semantic bridge.
- decision: `.athena` project source remains SSOT for actual device instances, ports, connections, and layout intent.
- decision: Large SVG bodies may be external, but the logical Athena element contract must stay compileable and understandable.
- (decision) Party review adopted: project .athena source owns actual device instances, ports, connections, and layout; Symbol and Element sources own reusable representation contracts only.
- (decision) Direction and signal in Symbol/Element are compatibility predicates, never project-port truth; SVG cannot declare them.
- (decision) Presentation Profile and Binding Resolver remain first-class typed boundaries; M34 replaces XML serialization and duplicated semanticType authority rather than collapsing policy into Element.
- (decision) SVG input is compiled through a closed safe subset into Graphic Primitive IR; raw SVG DOM never reaches the renderer.
- (decision) M34 uses four vertical value epics and every epic must produce Cabinet-visible or structured end-to-end proof.
- (decision by user) User selected Athena DSL as the sole canonical authoring and SSOT for symbols, elements, profiles, and bindings; XML and annotated SVG are import/export only, never product authority.
- (decision) Native typed Athena graphic bodies are the default; optional external SVG is compile-time geometry only.
- (decision) Element is a visual representation, not an engineering component definition; a component system is deferred beyond M34.
- (decision) Public Athena vocabulary remains small and domain-facing; compiler/runtime names do not become source declarations.
- (superseding decision by user) Simple representations use native Athena; complex representations
  may be one governed annotated SVG using `data-athena-schema="representation/v1"` and a closed
  `data-athena-*` profile on selected nodes.
- (superseding decision) Each definition has exactly one source authority. Native Athena and
  annotated SVG cannot merge or duplicate one identity; both compile through Athena-owned validation
  into the same canonical definition and Graphic Primitive body.
- (decision) Annotated SVG owns reusable representation contracts only. Project devices, actual
  ports/connections, classification, layout, Profile, Binding, package policy, raw runtime markup,
  and XML manifests remain forbidden.
