- (decision) M36 focuses one product surface: professional Cabinet connection topology and composition; Documentation and Schematic remain out of scope.
- (decision) Athena source remains the engineering metadata authority; SVG may expose geometry references only, while ports, direction, signal, compatibility, and parameters remain in typed Athena source.
- (decision) ELK may be used behind an Athena planner adapter for placement and routing proposals; it cannot own semantic meaning, source mutation, occurrence identity, or persisted layout truth.
- (change) External review reframes M36 as Engineering Connectivity Semantics consumed by Cabinet, not as a Cabinet drawing polish milestone.
- (decision) Use Connectable Entity Contract instead of Component contract because Athena already has M14 component knowledge and M36 must not redefine it.
- (decision) M36 formally separates semantic, representation, physical, and planner-owned constraints and introduces Route Intent between Connection and Route Fact.
- (decision) Engineering Lowering produces transient Connection IR and Layout Graph; these are disposable compiler IR, never persisted engineering truth.
- (event) Expert review reconciled into draft PRD and addendum; draft remains open for user approval.
- (decision) M36 planner authority runs in the Kotlin compiler so source-first compilation, traceability, and deterministic facts do not depend on frontend lifecycle.
- (decision) M36 Core uses an Athena-native deterministic baseline planner; ELK remains an optional JVM adapter after the core contract and normalization proof pass.
- (decision) M36 admits only data-athena-ref as SVG geometry-reference vocabulary; any additional SVG extension needs a later versioned proposal.
- (decision) M36 Cabinet proof uses package-defined electrical connection categories: power.ac, power.dc, control.digital, control.analog, and protective-earth; the core language remains domain-neutral.
